# API.md - Endpoint Reference

Base URL: `http://localhost:8000`. All `/api/v1/*` routes except the OAuth ones
require `Authorization: Bearer <session_token>` (obtained from the OAuth callback).

A live, always-in-sync version of this reference is auto-generated by FastAPI at
`GET /docs` (Swagger UI) and `GET /openapi.json` (raw OpenAPI 3.1 spec) - this file
exists as a static reference per the assignment's submission requirements; see
[docs/openapi.json](docs/openapi.json) for a checked-in snapshot and
[docs/postman_collection.json](docs/postman_collection.json) for a ready-to-import
Postman collection.

---

## `GET /api/v1/auth/google`

Starts the OAuth2 login flow. Redirects the browser to Google's consent screen.
No auth required (this IS the auth flow).

**Response:** `302 Found` redirect to `accounts.google.com`.

## `GET /api/v1/auth/google/callback?code=...`

Google redirects here after the user grants consent. Exchanges `code` for tokens,
upserts the `User` row (tokens encrypted at rest), issues a session JWT.

**Response `200`:**
```json
{"session_token": "eyJhbGciOi...", "user_id": "3fa85f64-...", "email": "you@gmail.com"}
```

## `POST /api/v1/query`

The main orchestration endpoint.

**Request:**
```json
{"query": "Cancel my Turkish Airlines flight", "conversation_id": "optional-uuid"}
```
(`conversation_id` is accepted for shape-compatibility with the brief; conversation
context is actually resolved automatically per-user from the last 5 turns, so it's
safe to omit.)

**Response `200`:**
```json
{
  "response": "I found your Turkish Airlines booking (TK1234) in an email from Oct 15.\n✓ Calendar event \"Istanbul → NYC Flight\" on Nov 5 at 10:30 AM\n✓ Drafted cancellation email to support@turkishairlines.com\n\nWould you like me to send it?",
  "actions_taken": ["found booking email", "found calendar event", "drafted cancellation email"],
  "intent": {
    "services": ["gmail", "gcal"],
    "intent": "cancel_flight",
    "entities": {"airline": "Turkish Airlines"},
    "steps": ["search_gmail_for_booking", "find_calendar_event", "draft_cancellation_email"],
    "needs_clarification": false,
    "clarification_question": null
  },
  "conversation_id": "b3f1c2a0-..."
}
```

**Ambiguous-query response** (e.g. `"Move the meeting with John"`, two Johns on the
calendar) - the plan/executor/synthesizer stages are skipped entirely:
```json
{
  "response": "You have multiple meetings with people named John. Which meeting, and what new time?",
  "actions_taken": [],
  "intent": {"services": ["gcal"], "intent": "reschedule_event", "needs_clarification": true, "...": "..."},
  "conversation_id": "..."
}
```

**Errors:**
- `401` - missing/invalid/expired session token.
- `429` - rate limit exceeded (100 queries/user/hour): `{"detail": "User ... exceeded 100 queries/hour"}`.

## `POST /api/v1/sync/trigger`

Enqueues an immediate Gmail+Calendar+Drive sync for the current user (Celery task),
instead of waiting for the next 15-minute scheduled sync.

**Response `200`:**
```json
{"task_id": "c1a2...", "status": "queued"}
```

## `GET /api/v1/sync/status`

Last sync outcome per service for the current user.

**Response `200`:**
```json
[
  {"service": "gmail", "last_synced_at": "2026-09-17T10:15:00Z", "status": "ok", "error": null},
  {"service": "gcal", "last_synced_at": "2026-09-17T10:15:02Z", "status": "ok", "error": null},
  {"service": "gdrive", "last_synced_at": "2026-09-17T09:59:58Z", "status": "error", "error": "Drive API rate limit exceeded"}
]
```

## `GET /health`

Liveness check (no auth). `{"status": "ok"}`. Used by the docker-compose healthcheck
pattern / a load balancer's health probe.
